# 局域网剪贴板

电脑和手机打开同一个网页，一端输入另一端实时出现，点一下就复制。截图、安装包、PDF 也能互传。

不装任何第三方库 —— Python 标准库 + 一个 HTML 文件。

## 用法

### 桌面图标（推荐）

装一次，以后双击桌面图标就能用：

```powershell
pwsh install.ps1
```

桌面会出现「局域网剪贴板」图标，双击即启动服务并自动打开浏览器。
图标路径自适应 —— 项目放在哪就指向哪，不写死任何绝对路径。

卸载：`pwsh install.ps1 -Uninstall`

### 命令行启动

```powershell
pwsh start.ps1
```

启动后终端会打印两个地址：

```
局域网剪贴板已启动
  本机   http://127.0.0.1:8900
  手机   http://192.168.1.23:8900     ← 手机连同一个 WiFi 后打开这个
```

手机连同一个 WiFi，浏览器打开那个 `192.168.x.x` 地址就行（加个书签，下次直接点）。

常用参数：

```powershell
pwsh start.ps1 -Port 8901       # 换端口
pwsh start.ps1 -LocalOnly       # 只给本机用，不对局域网开放
pwsh start.ps1 -NoBrowser       # 不自动开浏览器
pwsh start.ps1 -Inbox D:\收件   # 换收件箱目录（默认是下载目录）
pwsh start.ps1 -NoInbox         # 不往收件箱落，只留在网页上
```

直接跑 Python 也行：`python server.py --port 8900`，
单个文件默认上限 200 MB，不够就加 `--max-file-mb 500`。

## 能做什么

**文字** —— 一个框，两端实时同步（SSE 推送）。停止输入 0.4 秒自动发出去。
上限 20 万字。

**整理断行** —— 从 PDF、邮件、网页粘过来的文案，一句话常被硬生生切成好几行。
点一下「整理断行」就把它们接回去，中英文都认：

```
整理前                                整理后
这是一段从 PDF 粘过来的文案，     →    这是一段从 PDF 粘过来的文案，中间被切成了
中间被切成了好几行。                  好几行。

The quarterly report shows      →    The quarterly report shows that revenue
that revenue increased by             increased by twelve percent.
twelve percent.
```

它不动这些：空行分出来的段落、`- 列表`、`1. 编号`、`# 标题`、`> 引用`、
表格，还有 ` ``` ` 围起来的代码块。英文那边还认几种常见情况 ——
`inter-` / `national` 拼回 `international`，`Dr.` `etc.` `e.g.` 后面的点
不当句号，PDF 那种每行都顶到头的定宽排版也认得出来，句号在行末照样接。

拿不准就点，**点完按钮会变成「撤销整理」，再点一下原样还回来**。
粘贴时如果发现有三处以上像是被切断的行，它只提醒一句，不替你动手。

**文件** —— 什么类型都收：截图、apk、zip、PDF、日志都行。
保留最近 20 个，单个上限 200 MB，`.data/` 总量上限 2 GB，哪条先到都会把最早的挤掉。

**收件箱 —— 传上来的文件会照原名直接落进你的下载目录**（`C:\Users\你\Downloads`），
不用在电脑上再点一次下载。网页上那份归网页管（会被上面那三条规则挤掉），
下载目录这份归你管，不参与淘汰，只有你自己删。

重名绝不覆盖：下载目录里已经有 `报表.xlsx`，新来的那个就叫 `报表-2.xlsx`。
换地方用 `-Inbox D:\收件`，不想要这个行为用 `-NoInbox`。

**收件记录** —— 收件箱里有个 `收件记录.txt`，每收一个文件追加一行，只追加不清理：

```
# 局域网剪贴板收件记录 —— 每收到一个文件追加一行，只追加，不会自己清理
2026-10-10 11:04:32     820 KB  C:\Users\你\Downloads\季度报表 最终版.xlsx
2026-10-10 11:04:32    48.0 MB  C:\Users\你\Downloads\门店演示视频.mp4
2026-10-10 11:04:32     820 KB  C:\Users\你\Downloads\季度报表 最终版-2.xlsx   (原名 季度报表 最终版.xlsx)
2026-10-10 11:04:32       3 KB  C:\Users\你\Downloads\日志_2026-10-10.txt   (原名 日志:2026-10-10.txt)
```

网页上那份列表只活在内存里，**进程一重启就空了**（浏览器刷新不会丢，那只是重新拉一次状态）。
这个文件是唯一能长期回答「那东西什么时候收到的、原名叫什么、落在哪」的地方。
落盘名被改过的会把原名写在后面 —— 重名排了号，或者名字里有 Windows 存不下的字符被换掉了。

电脑端可以 Ctrl+V 直接粘贴截图（从资源管理器复制的文件也认），也能拖进去；
手机端点一下选文件，想发照片或视频就按「相册 / 拍摄」。传大文件时有进度条。

收到的东西在下面排成**一行一条的流水**：后缀、文件名、大小、什么时候到的。
不做缩略图也不做预览 —— 文件本来就已经躺在下载目录里了，再把原图拉回来当封面是白花流量，
而且记录一多，一屏放不下几条就难翻了。

每条记录右边那个按钮**两头不一样**：

- 在跑服务的这台电脑上（`127.0.0.1`）显示「已存入」，点不动 ——
  文件早在收件箱里了，再点一次「下载」只会多出一份 `xxx (1).ext`。
- 别的设备（手机走 `192.168.x.x`）显示「下载」，这是它取文件的唯一入口。

「删」两头都有，删的是**网页上这条记录和 `.data/` 里的中转副本**，不碰下载目录里那份。

**两端同时在改** —— 后发的覆盖先发的。但如果你正在打字时对方改了内容，
页面不会抢你的光标，而是弹一条提示让你自己决定要不要用对方的。

## 几件要知道的事

**没有口令。** 同一个 WiFi 下任何人打开 `你的IP:8900` 都能看到你贴的内容、下载你传的文件，
也能改掉它们。公司网络、咖啡馆 WiFi 慎用，别往里放生产密码和客户数据。
只想自己用就加 `-LocalOnly`。

**手机第一次连不上，先查防火墙。** Windows 默认挡入站连接，用管理员 PowerShell 放行一次：

```powershell
New-NetFirewallRule -DisplayName '局域网剪贴板' -Direction Inbound -Protocol TCP -LocalPort 8900 -Action Allow -Profile Private
```

**手机上点「复制」偶尔会提示「已帮你全选」。** 不是坏了 —— 浏览器只在 HTTPS 或
localhost 下才允许网页自动写剪贴板，手机走的是 `http://192.168.x.x`，不满足条件。
页面已经依次试过标准接口和老接口，都被拦住时就退到「全选 + 让你长按拷贝」。
日常用下来绝大多数安卓 Chrome / iOS Safari 走老接口都能直接复制成功。

**文件下载一律是附件，图片除外。** 传上来的 `.html`、`.svg` 点开不会被当成网页执行。
网页上已经不做预览了，所以这条只在你手动开 `/api/files/{id}` 那种地址时才看得出来 ——
常见图片格式会原样显示，其余一律当附件下发。

**文字不落盘，重启就没了**（文件除外，它们暂存在 `.data/`，但进程重启后列表也是空的，
文件可以手动删）。这是个中转站，不是网盘 —— 真要留下来的东西去下载目录里拿，收件箱那份不受重启和淘汰影响。

## 开发

```
server.py          服务端：Board（共享白板）+ Broadcaster（SSE 广播）+ Handler（路由）
static/index.html  单页前端，CSS/JS 全内联
start.ps1          启动脚本
test_server.py     服务端测试，起真 server 打真 HTTP
test_tidy.mjs      「整理断行」算法测试（node 跑，不用装任何依赖）
.data/             文件暂存，已 gitignore
```

接口：

```
GET    /api/state              当前快照 {rev, text, updatedBy, updatedAt, files[], limits}
GET    /api/events             SSE，连上先推一份快照，之后每次变更推全量
PUT    /api/text               {text, clientId}
POST   /api/files?clientId=    body 是文件原始字节，类型看 Content-Type，文件名看 X-File-Name（URL 编码）
GET    /api/files/{id}         原文件（图片 inline，其余 attachment + octet-stream）
DELETE /api/files/{id}         删一个
DELETE /api/files              全删
```

上传下载都是 256 KB 一块流式搬运，传几百兆也不占内存。
落盘名一律 `{id}.bin`，原始文件名只存在内存里的元数据中，碰不到文件系统。

跑测试：

```powershell
python test_server.py     # 服务端
node test_tidy.mjs        # 整理断行
```

覆盖了文字往返与版本号、超长/类型错误的拒绝、任意类型文件的上传下载与字节一致性、
HTML/SVG 不得内联、个数与总量两种淘汰、超限拒收后连接仍可复用、
文件 id 的路径穿越防护、文件名清洗、SSE 首帧快照与增量推送、断开后订阅回收。

整理断行那套算法写在 `static/index.html` 里（这东西要的就是单文件，不拆），
`test_tidy.mjs` 把 `TIDY-START` ~ `TIDY-END` 之间那段源码抠出来单测 ——
它是纯函数不碰 DOM，所以能直接在 node 里跑。改算法时别删那两个标记。
